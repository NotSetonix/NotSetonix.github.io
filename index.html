Process

How I run a Minecraft project.

  1. 01

    Concept

    Pitch, references and a check that it fits the Marketplace and the brief.

  2. 02

    Scope

    Overview, requirements and acceptance criteria in Notion. No MVP guesswork.

  3. 03

    Brief

    Full asset list split into model, texture, animation, audio and dev tasks, each with an owner.

  4. 04

    Build

    One ClickUp task per asset. I check blockers daily and cut scope with MoSCoW if we slip.

  5. 05

    QA

    Numbered review rounds, multiplayer, save and reload, and world-update testing.

  6. 06

    Submit

    Content guide for Microsoft’s reviewers, fixes to approval, then post-launch updates.

Quality assurance

QA that gets packs through review.

I run QA on every pack I produce, and I’ve worked as a freelance QA tester at XP Games. I test multiplayer as host and client, save and reload, and fresh versus existing worlds after updates. Every bug report has repro steps, expected vs actual, a severity tag and video or screenshots.
